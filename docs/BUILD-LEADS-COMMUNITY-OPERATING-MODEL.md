# Proof & Signal XRPL — Build + Leads + Community Operating Model

Status: ACTIVE
Scope: International product and B2B market; Bulgaria as a local community/distribution node.

## Core loop

`BUILD + LEADS + COMMUNITY → VERIFY → DEMONSTRATE → OUTREACH → FEEDBACK → IMPROVE → PAID PILOT`

The three workstreams run in parallel. None should wait for another unless an evidence, safety or production-readiness gate explicitly requires it.

## 1. BUILD

Each material build must leave four outputs:

| Output | Requirement |
|---|---|
| Technical artifact | Reproducible code, schema, dataset, evidence object or report |
| Demo | Human-usable demonstration grounded in verified behavior |
| Education | English international source explaining the result and limits |
| Lead reason | One concrete workflow problem that justifies contacting a qualified buyer |

A build is not complete because a commit exists. It must have a verification state.

Allowed states:
- `ESTIMATED`
- `LOCAL VERIFIED`
- `LIVE VERIFIED`
- `PRODUCTION VERIFIED`

## 2. LEADS

Pipeline:

`DISCOVER → DEDUPLICATE → VERIFY WORKFLOW → VERIFY CONTACT → OUTREACH → RESPONSE → WORKFLOW VALIDATION → PILOT`

Rules:
- no invented email addresses,
- no duplicate outreach,
- no company counted as qualified without a plausible operational fit,
- no silence counted as rejection,
- no revenue counted before confirmed payment.

## 3. COMMUNITY

International knowledge is authored in English first.

XRP Community Bulgaria may adapt useful material into Bulgarian for:
- beginners,
- local investors seeking factual education,
- developers,
- fintech and Web3 professionals,
- founders and businesses,
- meetup participants.

Community content must separate:
- verified fact,
- analysis,
- opinion,
- unknown.

The community is not used to promise returns, issue personalized investment advice or manufacture product credibility.

## 4. DISTRIBUTION REUSE

One verified technical result should be reused across surfaces:

```
VERIFIED BUILD
    ↓
REAL CASE
    ↓
ENGLISH TECHNICAL NOTE
    ↓
PRODUCT DEMO
    ↓
LEAD-SPECIFIC OUTREACH
    ↓
BULGARIAN COMMUNITY ADAPTATION
    ↓
MEETUP / DISCUSSION
    ↓
FEEDBACK
    ↓
NEXT BUILD
```

## 5. ANDROID OPERATIONS

The following must remain practical from Android:
- Gmail reply review and outreach approval/send,
- lead tracker update,
- GitHub PR/issue/build status review,
- meeting note capture,
- community posting,
- follow-up recording,
- KPI check.

Desktop/CI remains the preferred environment for heavy development, test suites and release packaging.

## 6. KPI SCORECARD

Track weekly:

- verified builds,
- live verified cases,
- qualified leads,
- outreach sent,
- replies,
- qualified conversations,
- community posts,
- community/member growth when measurable,
- meetings / introductions,
- pilot proposals,
- paid pilots,
- verified revenue.
